# Android / iOS 页面一致性清单

这份清单定义“页面一致”的验收口径：同一个业务状态下，两端都能进入对应页面，显示同一组核心信息，提供同一组主操作，并对成功、失败、重复提交和权限不足使用一致的结果语义。

## 已对齐的主流程

| 业务页面 | Android | iOS | 关键边界 |
| --- | --- | --- | --- |
| 登录 / 注册 | 已有 | 已有 | 登录失败保留页面，成功进入首页 |
| 首页 / 教练 | 已有 | 已有 | 无进行中计划时提示创建或加入计划 |
| 计划列表 / 详情 | 已有 | 已有 | 详情只允许创建者、参与者或有效邀请对象访问 |
| 创建计划 / 邀请 | 已有 | 已有 | 一个计划只允许一条邀请记录 |
| 每日打卡 | 已有 | 已有 | 计划外、重复日期、非参与者请求必须拒绝；照片在创建记录后按真实 `check_in_id` 上传 |
| 余额 / 充值 / 提现 / 支付方式 | 已有 | 已有 | 金额最低 0.01，按分处理；未绑定支付方式时两端均阻止提交，并提供绑定入口 |
| 排行榜 / 勋章 | 已有 | 已有 | 公开榜单只使用已审核数据 |
| 待处理邀请 / 二次确认 | 已有 | 已有 | 本地展示标记不能替代服务端状态 |

## 页面级 parity（代码层已对齐）

| 页面 | 当前差异 | 验收条件 |
| --- | --- | --- |
| 结算选择 | Android / iOS 均有独立结算页 | 两端调用统一结算选择接口，显示当前轮次、等待状态和仲裁状态，并阻止重复提交 |
| 打卡历史 | Android / iOS 均有独立页面 | 两端调用统一历史接口，按服务端权限查看本人和对手已审核记录 |
| 进度统计 | Android / iOS 均有独立页面 | 两端调用统一进度接口，显示当前体重、目标、进度百分比和打卡次数 |
| 计划评论 | Android / iOS 均有页面 | 两端统一调用 `/api/social/plans/{plan_id}/comments`，支持加载、发布、空状态和失败反馈 |
| 打卡照片 | Android / iOS 均有选择与预览入口 | 两端在创建打卡后调用 `/api/check-ins/{check_in_id}/photo/upload`，服务端校验归属、类型和 5MB 大小限制 |

## 交互状态规则

- `loading`：主操作禁用，显示加载反馈。
- `empty`：显示原因和下一步入口，不能只显示空白页面。
- `error`：保留当前页面内容，允许重试；服务端返回的业务错误优先展示。
- `success`：更新本地页面状态，再允许返回或继续下一步。
- `409`：按重复操作处理，不能显示成系统异常。
- `403`：显示无权限，并停止继续请求该资源。

## 验证边界

- 后端完整测试集使用 Python 3.7 环境验证。
- Android 原生构建需要本机 Android SDK；当前工作区缺少 `android/local.properties` 或 `ANDROID_HOME`。
- iOS 原生构建需要 macOS/Xcode；Windows 工作区只能完成静态审阅，不能把静态通过当作编译通过。
- 当前页面结构、接口路径和主题令牌已完成代码层对照；真机逐页截图仍需在对应构建环境中复核。
